## **4. How response speed should be measured**

Simply recording how quickly a model finishes typing is insufficient. Two measurements are useful:

**A. Time to First Token (TTFT)**

Time between sending the request and receiving the first generated token.

\\[ TTFT = T\_{\text{first token}}-T\_{\text{request}} \\]

This measures how quickly the model begins responding.

**B. Total Response Time**

Time between sending the request and receiving the completed answer.

\\[ T\_{\text{total}}=T\_{\text{completion}}-T\_{\text{request}} \\]

This measures how long the user waits for the complete answer.

Also record output tokens per second:

\\[ TPS=\frac{\text{Output tokens}}{\text{Generation time}} \\]

Use streaming API responses to capture these measurements.

**Recommended procedure:**

1. Use the same computer, internet connection and geographic region.
2. Send each question to both APIs ten times.
3. Alternate which model receives each request first to reduce ordering bias.
4. Use the same reasoning level and disable external tools.
5. Record TTFT, total response time and output tokens per second.
6. Calculate the median of the ten measurements for each question.
7. Calculate the overall median across all 50 responses per model.

This produces a more reliable comparison than timing a single response.

## **7. Limitations and considerations**

There are several important limitations to this comparison.

1\. **No direct testing:** I cannot access both external APIs in this conversation to execute the experiment or verify their live response times.

2\. **Knowledge cutoffs:** Google's Gemini 4 Hydrogen model card lists March 2026 as its knowledge cutoff, while xAI's Grok 4.7 documentation lists May 2026. These differences can influence answers to recent factual questions.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://deepmind.google\&sz=32)

Model Card — Google DeepMind+1



3\. **Network latency:** API response time includes network conditions, server queues and infrastructure overhead, not just model processing time.

4\. **Reasoning differences:** Identical reasoning labels do not necessarily mean identical computational effort.

5\. **Small sample size:** Five questions are suitable for a demonstration but insufficient to establish general factual reliability.

6\. **Benchmark bias:** Both companies publish their own performance evaluations. Their reported results should not be treated as independent head-to-head evidence.

7\. **Model updates:** Even when model identifiers remain unchanged, providers can update their serving infrastructure or model implementations. Record the date, model ID and API response metadata.
